# FloodWatch implementation outcomes

> The approved Chennai demo functionality is complete. The user rejected the prior UI refresh, so the contemporary visual redesign is now open; all illustrative-data and local-only safety boundaries remain in force.

- [x] **Map-first Chennai safety map and overlays** — Build the citizen-facing interactive map as the central screen, occupying approximately 60–70% of the available mobile screen. Render a dark-styled Google Static Maps image through the existing API server's bounded `/api/maps/static` endpoint; keep `MANUS_API_KEY` server-side and retain the map image's Google attribution. Provide pan, zoom, and selectable layers for rainfall, risk areas, infrastructure, distress reports, reservoirs, relief locations, and illustrative evacuation routes. Keep map interactions reachable on smartphones, provide a local schematic fallback if network imagery fails, and identify all simulated hazard overlays as demo-only.

- [x] **Rainfall outlook and risk notices** — Show illustrative color-coded rainfall intensity (green → yellow → orange → red), highlight high-risk zones, provide selectable 6h / 12h / 24h / 48h outlook periods, and compare sample Chennai/Tamil Nadu localities. Include a sample threshold-risk banner and a rain trend graphic. No weather provider is connected: figures are not real-time forecasts, no area-specific official push alert is sent, and visible labels must say “Demo data—not an official alert.”

- [x] **Citizen help requests and damage reports** — Keep “NEED HELP” visible on the map. Let a citizen create a local distress report with location selected by map pin (and location permission if available), emergency type (flood, stuck, medical, infrastructure damage), optional photo, and description; pin saved reports on the current user's map and provide an acknowledgement/status tracker on that device. Let a citizen report infrastructure damage such as a broken road or flooded bridge by selecting a map location. Reports are stored locally on the current device only; they are not transmitted to authorities or visible to other users. Never claim that help was dispatched.

- [x] **Infrastructure impact forecast** — Provide a selectable illustrative overlay for roads, bridges, power lines, and buildings in flood-risk zones. The impact panel should identify sample roads likely to be submerged and an alternative route, bridges at risk of closure, waterlogging-prone locations, and an estimated affected population. Mark these impacts and routes as sample scenarios, not a survey or official prediction.

- [x] **Reservoir levels and gate-release scenarios** — Show illustrative Chennai/Tamil Nadu reservoir markers. Selecting one should show capacity percentage, inflow versus outflow, Safe / Watch / Warning / Danger / Critical alert state, and a historical fill-trend mini chart; the accompanying level palette should distinguish blue Safe (<50%), yellow Watch (50–75%), orange Warning (75–90%), and red Danger (>90%). An explicitly illustrative release scenario should highlight sample downstream locations, estimated hours to impact, red evacuation zones, green safe zones/relief camps, and an evacuation route. Any affected-area banner may state the sample reservoir, simulated time-to-impact, suggested demo route, and sample nearest relief camp, but must not assert a live gate opening or verified evacuation instruction.

- [x] **Public dashboard, My Area, and local status** — Provide a bottom sheet/panel showing sample rainfall statistics by district/locality, active device-local distress-report count, reservoirs at warning/danger levels, infrastructure-damage report count, and illustrative affected-population estimate. Add a “My Area” choice for a Chennai locality/district and personalize demo alerts and local report status. Make it clear that the dashboard is illustrative and not a live official service.

- [x] **Accessible, bilingual, offline-friendly interface** — Deliver a clean dark-mode, mobile-responsive interface for common non-technical citizens, with large readable text, high-contrast color-blind-friendly risk indicators that also have text/icons, and short animated panel/banner transitions. Provide English and Tamil for primary navigation, actions, and safety-critical prototype notices. Cache last-known demo alerts with a timestamp and preserve locally created reports on-device for offline use.

- [x] **Prototype trust boundaries and emergency contacts** — Clearly label weather, reservoir telemetry, impact estimates, maps' risk scenarios, routes, contacts, camps, and responder/volunteer workflow as demonstration-only unless a field is independently verified. Show emergency-contact examples without inventing contact details, and make the local-only report and lack of dispatch clear before submission. No verified external weather feed, government dam feed, cross-user report service, official notification channel, responder coordination, authenticated authority access, or separate operational admin panel is configured in this approved scope. The app is not for safety or evacuation decisions.

- [ ] **2026 native visual redesign** — Use React Bits, Animos.app, Magic UI, ARC UI, Swishy UI, Planes UI, Scrolltide/ScrollTides, Watermelon UI, Kokonut UI, Smooth UI, Animaster, and other relevant UI references to give this app a distinctly contemporary mobile design—not a generic or legacy-looking dashboard. Keep the fixed Expo/React Native starter: adapt useful ideas into native components rather than importing web-only DOM components, animation editors, or WebViews into core screens. Redesign the map overlays and dashboard hierarchy for portrait phones; remove clipped horizontal metrics, cramped/tiny text, overlapping footnotes, duplicated help calls-to-action, and map overlays that obscure neighborhoods. Add a clear labeled bottom navigation, readable 44dp+ touch targets, large values, generous spacing, focused selected-location sheets, scroll-led impact and report timelines, crisp severity colors paired with text/icons, and restrained reduced-motion-friendly transitions. Review layout at 390×844 in both English and Tamil. Preserve map/report functionality, accessibility, offline state, bilingual safety copy, and all demo-only/local-only boundaries.
